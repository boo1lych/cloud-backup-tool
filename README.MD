# ☁️ Cloud Backup Tool

[Скачать последнюю версию](https://gl.bi-telco.com/AAntonov/cloud-backup-tool/-/releases)

Утилита с графическим интерфейсом для автоматического резервного копирования локальных папок на любой (сетевой) диск или в облачное хранилище (предварительно подключенное как сетевой диск).

Приложение работает в фоне, сворачивается в системный трей и позволяет настроить гибкое расписание для разных папок.

## ✨ Возможности

- 📂 **Профили**: возможность создания нескольких профилей для разных задач (например, отдельно для Документов и отдельно для Файлов Outlook). Поддерживается создание, переименование, дублирование и удаление профилей.
- ⏰ **Два режима триггера бэкапа**:
  - **Run by schedule** — бэкап по расписанию (ежедневно, еженедельно, по интервалу).
  - **On file change** — бэкап по изменению файлов в monitored директориях (event-driven режим через watchdog).
- 🚀 **Автозапуск**: опциональный запуск при старте Windows с возможностью сразу свернуть в трей.
- 🚫 **Исключения**: игнорирование временных и системных файлов по маскам (например, `~$`, `*.tmp`, `logs/*`).
- 🔗 **Безопасность**: автоматический пропуск символических ссылок и ярлыков, чтобы избежать циклического копирования.
- 📊 **Подробное логирование по профилям**: каждый профиль ведёт собственный лог в `logs/profiles/<имя_профиля>.log`. В интерфейсе отображается лог активного профиля; при переключении — автоматически подгружается. Все ошибки копирования (какой файл, по какой причине) попадают в общий `errors.log` с подробностями.
- 🔄 **Повторные попытки**: настройка автоматических повторных попыток при ошибках (недоступность диска, нехватка места, пропадание источника, ошибки копирования, проблемы с закрытием процессов, таймаут).
- 🎯 **Управление процессами**: автоматическое закрытие указанных процессов перед бэкапом и их восстановление после завершения (например, Outlook перед копированием файлов почты).
- ⏱️ **Таймаут бэкапа**: ограничение максимального времени выполнения бэкапа.
- 🎬 **Действия при отказе**: выполнение скриптов или показ уведомлений после исчерпания всех попыток.
- ⚠️ **Индикатор ошибок**: визуальное уведомление в главном окне о наличии ошибок в логе.
- 📢 **Уведомления в VK Teams (Mail.ru)**: отправка алертов об ошибках бэкапа в указанные чаты (мгновенные при критических сбоях до запуска, агрегированные по итогам сеанса).
- 🎨 **Темы оформления**: поддержка светлой и тёмной темы интерфейса.
- 💾 **Минимизация в трей**: программа продолжает работать в фоне, не занимая место на панели задач.

## 🚀 Быстрый старт (Для пользователей)

### Шаг 1. Подготовка облака / сетевого диска

Убедитесь, что ваше облачное хранилище (Яндекс Диск, Dropbox, Google Drive через RAIDrive и т.д.) подключено к компьютеру как обычный сетевой диск (например, диск `O:`).

### Шаг 2. Запуск программы

1. Скачайте последнюю версию программы (архив `CloudBackupTool.zip`) из раздела [Releases](https://gl.bi-telco.com/AAntonov/cloud-backup-tool/-/releases).
2. Распакуйте архив в удобное место (например, в `C:\Programs\CloudBackupTool`).
3. Запустите файл `CloudBackupTool.exe`.

### Шаг 3. Настройка профиля

1. В открывшемся окне перейдите в раздел нужного профиля (по умолчанию это `Default`).
2. **Source Directories**: нажмите `Add...` и выберите локальные папки, которые нужно копировать.
3. **Backup Destination**: нажмите `Browse...` и выберите папку на вашем сетевом диске (например, `O:\MyBackups`).
4. **Profile Control**:
   - Поставьте галочку `Enabled`, чтобы профиль стал активным.
   - Выберите **Trigger mode**:
     - **Run by schedule** — бэкап по расписанию. В `Backup Schedule` выберите:
       - `Daily 23:00` / `Daily 18:00` / `Daily 10:00` — ежедневный бэкап в указанное время.
       - `Custom` — пользовательское расписание: время в формате `HH:MM` (например, `21:30`) или интервал в минутах (например, `120`).
       - `Weekly` — еженедельный бэкап с выбором дней недели и времени.
     - **On file change** — бэкап запускается автоматически при изменении файлов. Дополнительно настраиваются:
       - Фильтры событий (Create/Modify, Delete, Rename).
       - `On queue overflow` — поведение при переполнении очереди событий:
         - `run_immediately` — немедленный полный бэкап.
         - `run_by_schedule` — использовать расписание из `Backup Schedule`.
         - `log_warning` — только логирование, без действий.
5. Нажмите кнопку **► Start** для немедленного запуска или просто оставьте программу работать — она сама сделает бэкап по расписанию или при изменении файлов.

## 🛠️ Расширенные настройки

### Управление процессами (вкладка Process Control)

Если некоторые программы блокируют файлы во время бэкапа (например, Outlook блокирует файлы PST/OST), можно настроить их автоматическое закрытие:

- Включите `Enable process control`.
- Добавьте имена процессов (например, `OUTLOOK.EXE`).
- Выберите режим закрытия:
  - `graceful` — мягкое завершение через `WM_CLOSE` (окно получает стандартный запрос на закрытие, приложение может сохранить данные).
  - `force` — принудительное завершение (аналог `kill`, данные могут быть потеряны).
  - `graceful_then_force` — сначала мягкое, затем принудительное (рекомендуется).
- Настройте таймаут ожидания и действие при ошибке закрытия.
- Выберите, восстанавливать ли процессы после бэкапа.

> **Примечание**: в режиме `On file change` вкладка Process Control недоступна — event-driven бэкап работает только с изменёнными файлами и не требует закрытия процессов.

### Повторные попытки (вкладка Retry Settings)

Если бэкап завершился с ошибкой, программа может повторить его автоматически:

- Включите `Enable retry`.
- Укажите максимальное количество попыток и интервал между ними.
- Выберите типы ошибок, при которых нужно повторять. Поддерживаются:
  - `Disk unavailable` — целевой диск недоступен (отвалился сетевой диск, USB и т.д.).
  - `Low disk space` — на целевом диске осталось менее 1 ГБ свободного места.
  - `Source missing` — одна из исходных папок недоступна.
  - `Copy errors` — ошибки при копировании файлов (нет прав, файл занят и т.д.).
  - `Process close failed` — не удалось закрыть процесс из списка `close_before`.
  - `Timeout exceeded` — превышен общий таймаут бэкапа.
- Настройте действия при полном отказе (после исчерпания всех попыток):
  - `run_script` — запуск скрипта (.bat, .ps1, .exe).
  - `show_message` — показ уведомления.

> **Примечание**: в режиме `On file change` вкладка Retry Settings недоступна.

### Общий таймаут

В разделе `Total Timeout` можно ограничить максимальное время выполнения бэкапа (в минутах). Если бэкап не укладывается в это время, он будет прерван.

### Индикатор ошибок

В правом верхнем углу главного окна отображается индикатор ошибок (⚠). При клике на него открывается окно с последними ошибками из лога.

### Уведомления в VK Teams (Mail.ru)

Программа может отправлять алерты об ошибках бэкапа в чаты VK Teams. Это удобно для оперативного реагирования, если вы не сидите за компьютером.

**Настройка**:

1. Откройте `Preferences` → `VK Teams Alerts`.
2. Поставьте галочку `Enable notifications`.
3. Укажите `Bot Token` (токен бота, созданного в VK Teams; поле скрыто за символами `•`).
4. Добавьте один или несколько `Chat ID` (идентификаторов чатов, куда будут приходить алерты) с помощью кнопок `Add...` / `Remove`.
5. Нажмите `Send Test Message` для проверки — в указанные чаты должно прийти тестовое сообщение.
6. Нажмите `OK` для сохранения.

**Что и когда отправляется**:

- 🚨 **Мгновенный алерт** при критических ошибках до запуска бэкапа (недоступен целевой диск или нет свободного места).
- ⚠️ **Агрегированный алерт** по итогам сеанса, если бэкап завершился успешно, но были ошибки в ходе выполнения (например, первая попытка провалилась, вторая — успешна).
- 🚨 **Агрегированный алерт** при total failure (все попытки исчерпаны).
- ⏱️ **Агрегированный алерт** при превышении таймаута.
- ❌ Алерт **НЕ отправляется** при ручной остановке бэкапа пользователем (кнопка Stop).
- ❌ Алерт **НЕ отправляется** при прерывании из-за сбоя закрытия процессов (`on_close_failure = abort`).

**Пример формата алерта**:

```
🚨 Ошибка: disk_unavailable
📁 Профиль: Outlook
📝 Детали: Target path is not available: 'Z:\backup'
🔻 Подробности (3 файла):
  • Z:\backup\file1.txt: Permission denied
  • Z:\backup\file2.txt: Access denied
  • Z:\backup\file3.txt: Disk full
⏰ Время: 2026-09-19 14:30:15
🔄 Попытка: 2/3
```

> **Примечание**: Лимит VK Teams — около 4000 символов. Если список файлов с ошибками превышает 10 записей, в алерте показываются первые 10 и указание `... и ещё N файлов`.

### Логирование по профилям

Каждый профиль ведёт собственный файл лога в папке `logs/profiles/`:

- При переключении профиля в основном окне автоматически подгружаются последние 10 000 строк из его лога.
- Системные сообщения (например, `Start All: launched 3 profile(s).`, `Schedule (profile 'X'): daily at 15:05`) записываются во все логи профилей.
- При переименовании профиля файл лога автоматически переименовывается. Если файл с новым именем уже существует, к нему добавляется суффикс `_1`, `_2` и т.д.
- При удалении профиля файл лога сохраняется как архив.

**Файл `errors.log`**

Содержит только ошибки. При сбое копирования в него попадают не только краткое описание (тип ошибки, номер попытки), но и подробности — список конкретных файлов с причинами сбоя (до 50 строк, далее `... and N more`). Это избавляет от необходимости искать детали в основном логе.

Многострочные записи (когда у одной ошибки есть список файлов-подробностей) считаются одной ошибкой — и в индикаторе `⚠ [N errors]`, и в окне `Error Summary`.

**Структура папки логов**:

```
logs/
├── errors.log                    ← общий лог ошибок с подробностями (ротация: 5 МБ, 5 файлов)
├── error_notifications.log       ← лог отправки алертов в VK Teams (ротация: 2 МБ, 3 файла)
└── profiles/
    ├── Default.log
    ├── Outlook.log
    └── ...
```

### Темы оформления

В меню `Preferences` → `Theme` можно выбрать светлую или тёмную тему интерфейса.

## 📡 Event-driven режим (On file change)

Режим `On file change` запускает бэкап автоматически при изменении файлов в monitored директориях, вместо периодических проверок по расписанию. Это удобно для папок с высокой активностью, где важно сохранять изменения почти в реальном времени.

### Как это работает

- Программа отслеживает файловые события (создание, изменение, удаление, переименование) через библиотеку watchdog.
- На Windows дополнительно детектируется переполнение очереди событий через системный API `ReadDirectoryChangesW`.
- После последнего события выжидается пауза (debounce, 5 секунд) перед запуском бэкапа — это позволяет собрать пачку изменений и не запускать бэкап на каждое движение файла.
- Во время выполнения бэкапа новые события накапливаются в буфере. После завершения бэкапа, если были изменения — запускается ещё один бэкап (pending backup).
- Каждые 30 секунд проверяется доступность source_dirs. Если папка "отвалилась" и вернулась — запускается полный бэкап.

### Инкрементальный бэкап

В event-driven режиме копируются только изменённые файлы из событий watchdog, а не вся папка целиком. Также синхронизируются удаления и переименования с backup_dir — это делает бэкап точной копией источника.

### Настройки

- **Фильтры событий**:
  - `Create/Modify files` — отслеживать создание и изменение файлов.
  - `Delete files` — отслеживать удаление файлов.
  - `Rename files` — отслеживать переименования.
- **On queue overflow** — поведение при переполнении очереди событий (когда файловых изменений слишком много):
  - `run_immediately` — немедленно запустить полный бэкап.
  - `run_by_schedule` — использовать расписание из `Backup Schedule` (показывается dropdown с выбором расписания).
  - `log_warning` — только логировать предупреждение, без действий.

### Индикатор мониторинга

В Profile Control отображается индикатор `Monitoring: ON/OFF`:

- **ON** (зелёный) — EventMonitor активен, профиль отслеживает изменения.
- **OFF** (серый) — мониторинг не запущен (профиль выключен, или выбран режим `Run by schedule`).

### Ограничения режима

- Вкладки `Process Control` и `Retry Settings` недоступны — event-driven бэкап работает только с изменёнными файлами и не требует закрытия процессов или повторных попыток.

## 🛠️ Сборка из исходников (Для разработчиков)

Если вы хотите собрать программу самостоятельно или внести изменения в код:

1. Убедитесь, что у вас установлен Python 3.8+.
2. Установите зависимости:
   ```bash
   pip install -r requirements.txt
   ```
   (включая `watchdog` для event-driven мониторинга)
3. Запустите скрипт сборки:
   ```bash
   build.bat
   ```
   Скрипт автоматически очистит старые артефакты, соберет `.exe` через PyInstaller и создаст папку релиза в директории `dist` с названием вида `CloudBackupTool - ГГГГ-ММ-ДД_ЧЧ-ММ-СС`. Внутри будут лежать готовые для распространения `.exe`, `bt2_config.json` и иконка.

## ⚙️ Конфигурация

Все настройки хранятся в файле `bt2_config.json`, который находится в той же папке, что и исполняемый файл. Программа автоматически сохраняет изменения, сделанные через графический интерфейс. Ручное редактирование файла не требуется, но возможно.

### Структура конфигурации (`bt2_config.json`)

- `global` — глобальные настройки (автозапуск, тема, активный профиль и т.д.).
- `profiles` — словарь профилей, каждый из которых содержит:
  - `source_dirs` — список исходных папок.
  - `backup_dir` — путь к папке бэкапа.
  - `trigger_mode` — режим триггера (`"schedule"` или `"file_change"`).
  - `backup_schedule` — расписание (`None`, `Daily HH:MM`, `Custom`, `Weekly`). В режиме `file_change` сохраняется предыдущее значение расписания.
  - `custom_time` — пользовательское время/интервал.
  - `weekly_days` / `weekly_time` — настройки еженедельного расписания.
  - `exclude_patterns` — маски исключений.
  - `event_filters` — фильтры событий для event-driven режима (`["created", "modified", "deleted", "moved"]`).
  - `on_queue_overflow` — поведение при переполнении очереди (`run_immediately`, `run_by_schedule`, `log_warning`).
  - `event_debounce_seconds` — пауза перед запуском бэкапа (по умолчанию 5 секунд).
  - `previous_schedule` — сохранённое расписание для восстановления при переключении режимов.
  - `process_control` — настройки управления процессами.
  - `retry` — настройки повторных попыток.
  - `total_timeout_minutes` — общий таймаут.

### Миграция старых конфигов

Если в старом конфиге `backup_schedule == "On file change"`, программа автоматически мигрирует его в `trigger_mode = "file_change"` при первом запуске.

### Конфигурация уведомлений в VK Teams (`error_notifications.json`)

Настройки алертов хранятся в отдельном файле рядом с основным конфигом:

```json
{
  "enabled": true,
  "bot_token": "ваш_токен_бота",
  "chat_ids": ["chat_id_1", "chat_id_2"]
}
```

- `enabled` — включены ли уведомления.
- `bot_token` — токен бота VK Teams.
- `chat_ids` — список идентификаторов чатов, куда отправляются алерты.

> **Примечание**: Этот файл редактируется через UI (`Preferences` → `VK Teams Alerts`). Ручное редактирование так же возможно. В текущей версии данные хранятся в открытом виде.
